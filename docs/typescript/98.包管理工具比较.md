# 99.包管理工具比较

## 1. npm（Node Package Manager） &#x20;

### 1.1 简介 &#x20;

npm 是 Node.js 官方默认的包管理器，随 Node 安装自动集成，用于管理依赖包、运行脚本和发布代码。&#x20;

官网/仓库：[https://www.npmjs.com/](https://www.npmjs.com/ "https://www.npmjs.com/") &#x20;

### 1.2 常用命令详解 &#x20;

#### 初始化项目 &#x20;

```bash 
npm init  # 交互式创建 package.json
npm init -y  # 快速生成默认配置的 package.json
```


#### 依赖管理 &#x20;

- **安装依赖**： &#x20;
  ```bash 
  npm install package-name  # 安装到 dependencies（生产依赖）
  npm install package-name --save-dev  # 安装到 devDependencies（开发依赖）
  npm install package-name@version  # 指定版本安装
  ```

- **更新依赖**： &#x20;
  ```bash 
  npm update  # 更新所有依赖到最新兼容版本
  npm update package-name  # 更新指定依赖
  npm outdated  # 查看过时依赖
  ```

- **卸载依赖**： &#x20;
  ```bash 
  npm uninstall package-name
  npm uninstall package-name --save-dev
  ```

- **查看依赖**： &#x20;
  ```bash 
  npm list  # 查看当前项目依赖树
  npm list package-name  # 查看指定依赖详情
  ```


#### 脚本运行 &#x20;

```bash 
npm start  # 运行 "scripts.start" 脚本
npm run script-name  # 运行自定义脚本
npm test  # 运行测试脚本
```


#### 其他常用命令 &#x20;

```bash 
npm cache clean --force  # 清除缓存
npm init -y && npm install  # 快速初始化并安装依赖
npm pack  # 打包当前项目为 tar 包
npm publish  # 发布包到 npm 仓库
```


### 1.3 特点与机制 &#x20;

- **依赖管理**：使用 **扁平依赖树**（通过 `node_modules/.package.json` 记录嵌套依赖），可能导致依赖重复安装。 &#x20;
- **版本控制**：基于语义化版本（SemVer），`^` 表示兼容大版本，`~` 表示兼容小版本。 &#x20;
- **性能**：安装速度较慢，尤其在处理大量依赖时。 &#x20;

## 2. yarn（Yet Another Resource Negotiator） &#x20;

### 2.1 简介 &#x20;

yarn 由 Facebook 开发，旨在解决 npm 早期版本的性能和依赖管理问题，支持离线模式和确定性安装。 &#x20;

官网/仓库：[https://yarnpkg.com/](https://yarnpkg.com/ "https://yarnpkg.com/") &#x20;

### 2.2 常用命令详解 &#x20;

#### 初始化与依赖管理（与 npm 对应） &#x20;

```bash 
yarn init  # 初始化项目
yarn add package-name  # 安装到 dependencies
yarn add package-name --dev  # 安装到 devDependencies
yarn add package-name@version  # 指定版本
yarn remove package-name  # 卸载依赖
```


#### 运行脚本与其他 &#x20;

```bash 
yarn start  # 运行脚本
yarn run script-name  # 运行自定义脚本
yarn install  # 安装所有依赖（等价于 npm install）
yarn cache clean  # 清除缓存
yarn offline  # 启用离线模式
```


#### 高级特性命令 &#x20;

```bash 
yarn why package-name  # 查看依赖存在的原因
yarn list --depth=0  # 查看顶层依赖
yarn upgrade-interactive  # 交互式升级依赖
```


### 2.3 特点与机制 &#x20;

- **性能优化**： &#x20;
  - 并行安装依赖，速度比 npm 快。 &#x20;
  - 使用 **yarn.lock** 文件确保依赖安装的确定性（相同锁文件生成相同依赖树）。 &#x20;
- **依赖管理**： &#x20;
  - 采用 **扁平依赖树**，但通过更优的算法减少重复依赖。 &#x20;
  - 支持 **workspaces**（工作区），用于管理多包项目。 &#x20;
- **离线模式**：可缓存依赖包，支持无网络环境安装。 &#x20;

## 3. pnpm（Performant npm） &#x20;

### 3.1 简介 &#x20;

pnpm 是新一代高性能包管理器，主打速度和磁盘空间优化，通过硬链接和符号链接管理依赖。 &#x20;

官网/仓库：[https://pnpm.io/](https://pnpm.io/ "https://pnpm.io/") &#x20;

### 3.2 常用命令详解 &#x20;

#### 基础命令（与 npm/yarn 对应） &#x20;

```bash 
pnpm init  # 初始化项目
pnpm add package-name  # 安装到 dependencies
pnpm add package-name -D  # 安装到 devDependencies（-D 等价于 --save-dev）
pnpm remove package-name  # 卸载依赖
pnpm install  # 安装所有依赖
```


#### 运行脚本与高级功能 &#x20;

```bash 
pnpm start  # 运行脚本
pnpm run script-name  # 运行自定义脚本
pnpm outdated  # 查看过时依赖
pnpm why package-name  # 查看依赖关系
```


#### 特有命令 &#x20;

```bash 
pnpm store prune  # 清理存储中的未使用依赖
pnpm recursive run test  # 在多包项目中递归运行测试
pnpm import  # 从 npm/yarn 锁文件导入依赖
```


### 3.3 特点与机制 &#x20;

- **依赖管理**： &#x20;
  - 使用 **内容寻址存储**（Content-Addressable Storage），通过硬链接共享全局依赖，减少磁盘占用。 &#x20;
  - 依赖树结构为 **非扁平模式**，避免幽灵依赖（未声明依赖不可用），更安全。 &#x20;
- **性能**： &#x20;
  - 安装速度极快，尤其在重复安装相同依赖时。 &#x20;
  - 支持 **workspaces** 和 **monorepo**（单仓多包）管理。 &#x20;
- **符号链接**： &#x20;
  - 项目本地依赖通过符号链接指向全局存储，避免重复下载。 &#x20;

## 4. 三者区别对比 &#x20;

| **维度**​   | **npm**​          | **yarn**​       | **pnpm**​                |
| --------- | ----------------- | --------------- | ------------------------ |
| **依赖管理**​ | 扁平依赖树，可能重复安装      | 扁平依赖树，减少重复      | 非扁平依赖树，硬链接共享依赖           |
| **安装速度**​ | 较慢（串行安装）          | 较快（并行安装）        | 极快（硬链接+缓存）               |
| **磁盘占用**​ | 高（重复依赖多）          | 中（优化重复依赖）       | 低（共享依赖）                  |
| **锁文件**​  | package-lock.json | yarn.lock       | pnpm-lock.yaml           |
| **幽灵依赖**​ | 存在（嵌套依赖可访问）       | 存在（同上）          | 不存在（仅声明依赖可访问）            |
| **多包管理**​ | 原生支持有限            | 支持 workspaces   | 强力支持 workspaces/monorepo |
| **社区生态**​ | 最广泛               | 广泛（尤其 React 生态） | 快速增长（现代项目首选）             |

## 5. 项目转换指南 &#x20;

### 5.1 npm 项目转 yarn &#x20;

1. **安装 yarn**： &#x20;
   ```bash 
   npm install -g yarn
   ```

2. **生成 yarn.lock**： &#x20;
   ```bash 
   yarn install  # 会自动读取 package.json 并生成 yarn.lock
   ```

3. **替换命令**： &#x20;

   将 `package.json` 中脚本的 `npm run` 改为 `yarn`（如 `npm start` → `yarn start`）。 &#x20;

### 5.2 npm/yarn 项目转 pnpm &#x20;

1. **安装 pnpm**： &#x20;
   ```bash 
   npm install -g pnpm  # 或 yarn global add pnpm
   ```

2. **导入依赖**： &#x20;
   ```bash 
   pnpm import  # 自动读取 package-lock.json 或 yarn.lock 并生成 pnpm-lock.yaml
   ```

3. **更新脚本命令**： &#x20;

   将脚本中的 `npm run`/`yarn` 改为 `pnpm`（如 `yarn start` → `pnpm start`）。 &#x20;

### 5.3 yarn 项目转 npm &#x20;

1. **移除 yarn.lock**： &#x20;
   ```bash 
   rm yarn.lock
   ```

2. **安装依赖**： &#x20;
   ```bash 
   npm install  # 生成 package-lock.json
   ```

3. **替换命令**： &#x20;

   将 `yarn` 改为 `npm run`（如 `yarn start` → `npm start`）。 &#x20;

### 5.4 注意事项 &#x20;

- **锁文件兼容性**：转换后建议提交新的锁文件（如 pnpm-lock.yaml），确保团队依赖一致。 &#x20;
- **命令差异**：部分高级功能（如 pnpm 的工作区）需手动配置，参考官方文档调整项目结构。 &#x20;
- **性能权衡**：pnpm 在大型项目中优势明显，但小型项目可根据团队习惯选择。
